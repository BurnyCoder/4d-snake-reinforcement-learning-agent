## Minibatch size on CUDA (batched env, 262,144 timesteps per row, 8 threads)

Measured after the grid above: the PPO update, not the environment, is the bottleneck, so fewer
and larger minibatches per rollout raise throughput.

| n_envs | batch_size | seconds | fps |
|---|---|---|---|
| 1024 | 2048 | 14.25 | 18,394 |
| 1024 | 8192 | 8.59 | 30,523 |
| 1024 | 16384 | 7.61 | 34,451 |
| 4096 | 2048 | 12.59 | 20,818 |
| 4096 | 8192 | 7.75 | 33,807 |
| 4096 | 16384 | 6.89 | 38,073 |

Defaults adopted: `SNAKE_N_ENVS=4096`, `SNAKE_BATCH_SIZE=8192` (32 minibatches x 4 epochs = 128
gradient steps per 262k-sample rollout), `SNAKE_DEVICE=auto` (= cuda here), `SNAKE_TORCH_THREADS=8`.
